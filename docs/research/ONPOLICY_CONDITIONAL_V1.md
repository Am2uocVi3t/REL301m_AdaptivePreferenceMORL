## Prospective decisions before code

- Same model, PPO/PopArt/MDMM, utility-preserving scalarization, eight streams,
  seed20264111,4M interactions, milestones500k/1M/2M/4M and optimizer counts as S.
  Fresh initialization; never load S weights or optimizer state.
- Exactly the existing32 training preferences generated by the existing
  `AdaptivePreferenceSampler` pool generator, seed20261001. Freeze their explicit
  float32 values in the C plan before training. No validation/test preferences
  are used to construct the pool.
- Uniform random selection of a pool index at each stream's initial reset and
  every episode end, using a separate NumPy Generator seeded by
  SeedSequence([20264111,20]). Independent draws with replacement. Uniform
  episodes do not imply equal interaction counts because episode lengths differ;
  save both draw counts and interaction counts for all32 weights.
- Keep weights fixed until terminal/time-limit reset, including across64-step
  fragments. Capture each transition's own preference, old log-prob and vector
  value without mutable aliases. Bootstrap the final pre-reset observation at
  the OLD preference; only then draw the next episode preference. TD1 stops at
  reset boundaries, as qualified in S.
- Snapshot all8 active pool indices plus local sampler RNG/draw and interaction
  counts, in addition to S's exact optimizer/environment/global RNG state.
- Frozen evaluation: same32 validation weights x3 seeds x2 modes, plus two task
  profiles x10 seeds x2 modes at each of four milestones:928 episodes, <=928k
  development steps, zero final-test. Retain native and scaled vector returns.
- Final-only gate: for EACH inference mode, BOTH task profiles must have>=8/10
  deliveries AND mean utility above profile-specific frozen idle utility.
  C fully passes only if both modes pass; a single-mode pass is reported as
  partial evidence, not silently selected. Positive ore count elsewhere is not
  evidence of appropriate preference control. No best-milestone selection.
- This is conditional feasibility, not adaptive allocation or a claim of PPO
  superiority. S/C use the same interaction budget; episode exposure differs.
  G confirmation, Lunar PPO and original matrix/final-test remain unlaunched.
- Preserve all completed S/P2 files. A separate C runner reuses S's immutable
  low-level checkpoint/environment/evaluation helpers and unchanged PPO module.
  Do not rewrite S runner to make old evidence appear source-current.
- Engineering ceiling is the remainder of original50k F0 ceiling:37,072 steps
  after S's12,928. Qualify real CUDA process-kill/resume and partial minibatches,
  preference/reset semantics and native terminal before clean committed launch.
- No automatic restarts, extensions, seed substitutions, confirmation dispatch
  or source changes while training. Process lease and launcher duplicate guard
  run before existing logs can be changed. Everything managed stays on D:.
