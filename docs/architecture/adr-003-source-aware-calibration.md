# ADR-003: Source-Aware Objective and Hypervolume Calibration

Status: accepted
Date: 2026-10-15

## Context

Calibration v1 estimated every scale and hypervolume reference from a 100,000-interaction Uniform-PCQN validation pilot. This worked for MO-Lunar-Lander but failed for Minecart: both sparse ore objectives were zero in all 480 validation returns, even though training archives contained nonzero ore returns. A fixed-pool control repair did not change that validation failure. Increasing the budget until a particular learner succeeds would make metric definition depend on policy convergence and consume course-scale compute before the protocol is frozen.

Minecart 1.3.2 exposes a deterministic `pareto_front(gamma, symmetric)` method derived from its configured mine geometry and reward model. The returned 20-point front is identical across the three checked seeds, and the environment configuration is pinned and hashable. MO-Lunar-Lander exposes no equivalent interface.

## Options considered

1. Increase the learned-policy pilot budget until Minecart returns nonzero ore. This preserves one source type but couples calibration to algorithm success and has no principled stopping rule.
2. Estimate sparse-objective magnitudes from exploratory training archives. This is cheap but post-hoc, biased toward nondominated discoveries, and not the predeclared v1 source.
3. Prefer a versioned authoritative environment reference front when available, otherwise use an independent validation-only fixed-pool pilot.

## Decision

Use option 3. Calibration v2 declares a source for each environment before execution. Minecart uses a versioned artifact generated by `Minecart.pareto_front(gamma=0.99, symmetric=true)` under pinned `mo-gymnasium==1.3.2` and a predeclared environment-config hash. The extractor must reproduce identical sorted points across three declared seeds. MO-Lunar-Lander uses three new Uniform-PCQN seeds, the shared fixed candidate pool, identity input scales, nominal dynamics, immutable validation preferences, and final pilot checkpoints only.

Both sources use the same deterministic scale and reference construction: inverse 95th-percentile absolute magnitude, followed by the scaled coordinatewise minimum minus the larger of 5% robust span and `0.01`. Every proposed reference must be strictly dominated by every point in its declared source. Final-test data is mechanically excluded.

## Trade-offs

- Source types differ across environments, but both are declared, reproducible, and independent of final-test feedback.
- Minecart calibration reflects authoritative reachable geometry rather than the performance distribution of the repository's current learner. This is desirable for a metric definition but does not establish that PCQN can cover that front.
- The package-provided front is an environment-specific capability, so dependency version, generator arguments, configuration hash, protocol hash, plan hash, sorted points, and points hash must all be versioned.
- Post-freeze controllability remains a separate Phase 3 diagnostic. A failed learner may legitimately obtain zero hypervolume; diagnostics cannot revise the frozen calibration.

## Revisit triggers

Revisit this decision if the environment package changes its front generator or default config, if a source audit shows the generated front is not achievable under the executable environment, or if a common authoritative geometry source becomes available for both course environments.
